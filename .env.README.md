# Environment Variables Configuration

This project requires environment variables to connect to Supabase and OpenAI services.

## Quick Start

1. **Copy the example file:**
   ```bash
   cp .env.example .env.local
   ```

2. **Start Supabase (if not already running):**
   ```bash
   pnpm db:start
   ```

3. **Get Supabase credentials:**
   ```bash
   supabase status
   ```
   
   Copy the following values to `.env.local`:
   - `NEXT_PUBLIC_SUPABASE_URL` → Project URL
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` → Publishable key
   - `SUPABASE_URL` → same as the project URL (Worker)
   - `SUPABASE_SERVICE_ROLE_KEY` → Secret key
   - `DATABASE_URL` → DB URL

4. **Configure the AI provider:**
   - This repo talks to an OpenAI-compatible API. Local default is DeepSeek.
   - Get a key from: https://platform.deepseek.com/api_keys
   - Set `OPENAI_API_KEY` and keep `OPENAI_BASE_URL=https://api.deepseek.com`

5. **Verify configuration:**
   ```bash
   node scripts/verify-env.js
   ```

## Required Variables

### Supabase (Local Development)
- `NEXT_PUBLIC_SUPABASE_URL` - Supabase project URL (public)
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` - Supabase publishable key (public)
- `SUPABASE_URL` - Supabase URL for the Worker (same host as the public URL)
- `SUPABASE_SERVICE_ROLE_KEY` - Supabase service role key (secret, server-only)
- `DATABASE_URL` - PostgreSQL connection string

### OpenAI-compatible provider (DeepSeek)
- `OPENAI_BASE_URL` - Provider base URL (`https://api.deepseek.com` for DeepSeek)
- `OPENAI_API_KEY` - Provider API key (secret)
- `OPENAI_KNOWLEDGE_MODEL` - Chat/analysis model (e.g. `deepseek-v4-pro`)
- `OPENAI_VISUAL_MODEL` - Image model (e.g. `deepseek-v4-flash-vision-exp`)
- `EMBEDDING_BASE_URL` - Embedding provider endpoint. DeepSeek publishes no
  embeddings API, so this is a different vendor from `OPENAI_BASE_URL`.
- `EMBEDDING_API_KEY` - Key for that provider, not the analysis key.
- `EMBEDDING_MODEL` - Embedding model ID, e.g. `text-embedding-v4`.
- `EMBEDDING_DIMENSIONS` - Vector width. Written into the `vector(N)` column
  by the hybrid-search migration, so changing it later requires rebuilding the
  index and re-embedding every chunk.

### Storage (S3-compatible)
- `SUPABASE_STORAGE_URL` - Storage API URL
- `SUPABASE_STORAGE_ACCESS_KEY` - S3 access key
- `SUPABASE_STORAGE_SECRET_KEY` - S3 secret key
- `SUPABASE_STORAGE_REGION` - Storage region

## Security Notes

⚠️ **IMPORTANT**:
- **Never commit** `.env.local` to version control
- `.env.local` is already in `.gitignore` - keep it there
- Only commit `.env.example` as a template
- All keys shown in `.env.example` are placeholders
- Use different keys for production vs development

## Production Configuration

For production deployment, set environment variables in your hosting platform:
- Vercel: Project Settings → Environment Variables
- Supabase: Use production project credentials
- OpenAI: Use organization API key with usage limits

## Troubleshooting

### `supabase start` fails
- Ensure Docker is running
- Check port availability (54321, 54322, 54323)
- Try `supabase stop` then `supabase start`

### OpenAI API errors
- Verify your API key is valid
- Check your OpenAI account has credits
- Ensure models are accessible in your region

### Database connection fails
- Verify Supabase is running: `supabase status`
- Check DATABASE_URL matches the output
- Ensure no other service is using port 54322
